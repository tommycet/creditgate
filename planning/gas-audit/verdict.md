# Gas Audit — CreditGateVault — 2026-08-05

## Verdict: OPTIMIZE

The contract is functionally correct and uses several good patterns (custom errors,
`Loan storage` pointers, immutable config). However there are 7 distinct non-behavioral
gas-optimization opportunities worth ~4,500–9,800 gas per typical loan lifecycle.
Type annotation: all line references point at `CreditGateVault.sol` unless a `(T)`
suffix indicates `CreditGateTypes.sol`.

## Findings (ranked by gas saved)

### G1. Storage packing — pack `owner` + `paused` together
- **File:** `CreditGateVault.sol:41-42`
- **Current:** `address public owner;` (slot N) and `bool public paused;` (slot N+1) —
  two storage slots, two SLOADs when both are read in the same call.
- **Suggested:** Declare `address public owner;` followed immediately by a `uint256`-
  sized block of packed flags, OR collapse `paused` into a single packed word with owner.
  Simplest no-API-change win: place `bool public paused;` *immediately* before `address
  public owner;` won't pack (address is 20 bytes, bool 1 byte → packable into one slot).
  Reorder so `paused` and `owner` are adjacent, packing both into slot base+0:
  ```solidity
  bool public paused;       // 1 byte
  address public owner;     // 20 bytes  ← same slot as paused
  ```
- **Savings:** ~2,100 gas on first `pause()`/`unpause()` SSTORE (one fewer cold slot
  touch) and ~100 gas per `onlyOwner` + `whenNotPaused` combined read.
- **Caveat:** external getters generated by the public visibility still work — packing
  does not change the ABI.

### G2. Cache `loan.borrower` once instead of three SLOADs in `submitEligibility`
- **File:** `CreditGateVault.sol:215, 257, 268`
- **Current:** `loan.borrower` is read on line 215 (`require`), line 257 (`BorrowerMismatch`),
  and line 268 (event). Each `loan.borrower` is a cold SLOAD after the struct pointer
  warmup window (~2,100 gas on first cold read, ~100 gas each subsequent warm read).
- **Suggested:**
  ```solidity
  address borrower = loan.borrower; // one SLOAD
  require(borrower == msg.sender, "NotBorrower");
  // ...
  if (attestation.borrower != borrower) revert BorrowerMismatch(borrower, attestation.borrower);
  // ...
  emit EligibilitySubmitted(loanId, borrower, attestation.limit, attestation.expiry);
  ```
- **Savings:** ~2 × 100 = ~200 gas (warm) per call; ~2,100 gas on the very first cold
  access within a new block's access window.

### G3. Cache `loan.borrower` in `drawLoan`
- **File:** `CreditGateVault.sol:287, 301, 337, 346, 349`
- **Current:** `loan.borrower` is read at least 5 times: line 287 (`require`), line 301
  (`borrowerSourceAddressHash` snapshot uses `msg.sender` — fine — but the commitment
  and disbursement below both reference `loan.borrower`), line 337, 346, 349.
- **Suggested:** `address borrower = loan.borrower;` after the state check, reuse it.
- **Savings:** ~4 × 100 = ~400 gas (warm) per `drawLoan`.

### G4. Cache `loan.collateralAmount` in `drawLoan`
- **File:** `CreditGateVault.sol:320, 349`
- **Current:** `loan.collateralAmount` is read in the collateral-ratio math (line 320)
  and again in the `LoanFunded` event (line 349). Two SLOADs of the same slot.
- **Suggested:**
  ```solidity
  uint256 collateral = loan.collateralAmount;
  uint256 collateralUsd18 = (collateral * SCALE_TO_18 * xrpUsd18dp) / 1e18;
  // ...
  emit LoanFunded(loanId, borrower, loanAmount, collateral, commitment);
  ```
- **Savings:** ~100 gas (warm) per `drawLoan`.

### G5. Unchecked arithmetic — `nextLoanId++`
- **File:** `CreditGateVault.sol:152`
- **Current:** `loanId = nextLoanId++;` — Solidity emits an overflow check.
- **Suggested:** Wrap in `unchecked` — `nextLoanId` starts at 1 and would require
  >2^256 deposits to overflow, which is physically impossible.
  ```solidity
  unchecked { loanId = nextLoanId++; }
  ```
- **Savings:** ~50–80 gas per `depositCollateral` (one fewer DUP + LT + jump sequence).

### G6. Unchecked arithmetic — `borrowerNonce` / `borrowerRevocationVersion` increments
- **File:** `CreditGateVault.sol:120-126`
- **Current:** Both increments are already guarded by `< type(uint32/uint8).max` checks,
  so they cannot overflow — yet Solidity still emits redundant overflow checks because
  the `+` happens outside `unchecked`.
- **Suggested:**
  ```solidity
  if (borrowerRevocationVersion[borrower] < type(uint8).max) {
      unchecked { borrowerRevocationVersion[borrower] += 1; }
  }
  if (borrowerNonce[borrower] < type(uint32).max) {
      unchecked { borrowerNonce[borrower] += 1; }
  }
  ```
- **Savings:** ~100–160 gas per `revokeEligibility` call (two overflow checks removed).

### G7. Custom errors instead of `require` string literals
- **File:** `CreditGateVault.sol:66, 71, 87-92, 134, 174, 194, 215, 244-249, 287, 367, 445`
- **Current:** Several `require(cond, "string")` sites use string revert reasons:
  - Line 66: `require(msg.sender == owner, "NotOwner")`
  - Line 71: `require(!paused, "Paused")`
  - Line 87-92: 5× constructor zero-address / zero-ratio checks
  - Line 134: `require(xrplAddressHash != bytes32(0), "ZeroHash")`
  - Lines 174, 194, 215, 287, 367: `require(..., "NotBorrower")`
  - Lines 244-249: `require(attestation.s <= ..., "BadSignatureS")` and `... "BadSignatureV"`
  - Line 445: `require(amount > 0, "NoCollateralToRecover")`
- **Suggested:** Replace each with a `revert <CustomError>()` (define new errors in
  `CreditGateTypes.sol`). Custom errors encode as a 4-byte selector instead of a string,
  saving deployment bytecode plus ~10–60 gas per revert path that is taken. The modifier
  bodies (`onlyOwner`, `whenNotPaused`) can call internal functions that revert with
  custom errors.
- **Savings:** ~40 gas per reverting path *actually hit* (likely rare in normal flow but
  meaningful for the `onlyOwner`/`whenNotPaused` paths that gate every external fn) plus
  ~150–300 bytes of deployment bytecode.

### G8. Dead / unreachable custom error
- **File:** `CreditGateTypes.sol:132` (`EligibilityNotYetValid`)
- **Current:** `error EligibilityNotYetValid(uint64 notBefore, uint64 now_);` is declared
  but **never reverted to** anywhere in `CreditGateVault.sol`. A grep across the repo
  would confirm; from the two audited files it is unused.
- **Suggested:** Remove the declaration (dead code) — saves deployment bytecode only,
  not call gas. Also reduces confusion for auditors.
- **Savings:** ~50 bytes bytecode; ~0 runtime gas.

### G9. Dead enum value `REPAYMENT_PENDING`
- **File:** `CreditGateTypes.sol:33` (`REPAYMENT_PENDING // 5`)
- **Current:** The `LoanState.REPAYMENT_PENDING` value (5) is never assigned in any state
  transition. The flow goes `FUNDED → CLOSED` (via `submitRepaymentProof`) or
  `FUNDED → DEFAULTED` (via `liquidate`), skipping `REPAYMENT_PENDING` entirely.
- **Suggested:** Remove `REPAYMENT_PENDING` from the enum OR add the intended
  intermediate transition. Removal saves ~0 runtime gas but tightens the state machine
  and reduces the enum's max ordinal from 8 to 7 (no packing impact since `state` shares
  a slot with two small fields either way).
- **Savings:** ~0 call gas; minor bytecode + clarity improvement.

### G10. `_computeCommitment` could be `pure`
- **File:** `CreditGateVault.sol:468-485`
- **Current:** Comment says "internal `view` (not `pure`) because it reads `address(this)`".
  `address(this)` is **not** a storage read — it is available in `pure` functions.
- **Suggested:** Change `internal view` → `internal pure`. This is a no-op for gas but
  tightens purity guarantees and may let the optimizer reason more freely. Strictly a
  correctness/clarity fix, not a gas win — listed because it touches the same review
  surface and is free.
- **Savings:** ~0 gas (compile-time clarity only).

## Notes on what is *already done well*
- `Loan storage loan` pointers (not `Loan memory`) throughout — avoids copying the
  entire struct.
- Immutables (`fxrp`, `usdt0`, `teeAuthority`, `collateralRatioBps`,
  `ftsoStalenessLimit`, `loanDuration`, `ftsoV2`, `fdcVerification`) — all config is
  immutable, so no SLOAD cost beyond the single MLOAD-loaded value.
- The `Loan` struct already packs `eligibilityExpiry` (uint64) + `eligibilityNonce`
  (uint32) + `state` (uint8) into one slot (slot index 5) — this is correct and saves
  2 slots vs. naive declaration. No further packing gain is available *without
  reordering* (which would change struct memory layout and any external `getLoan`
  consumers), and the bytes32 fields inherently each demand a full slot.

## Estimated total savings per tx

| Function          | Approx. savings (gas) |
|-------------------|------------------------|
| `depositCollateral` | ~50–80   (G5) |
| `requestEligibility` | ~100    (G2 partial — borrower SLOAD cached) |
| `submitEligibility` | ~200–2,300 (G2) |
| `drawLoan`         | ~500    (G3 + G4) |
| `revokeEligibility`| ~100–160 (G6) |
| `pause`/`unpause`  | ~2,100 first-touch (G1) |
| Reverting paths   | ~40 each (G7) |

**Aggregate per full loan lifecycle** (deposit → request → submit → draw → repay):
**~850–3,040 gas** in the happy path, plus deployment bytecode savings from G7/G8/G9
(~200–400 bytes). The G1 cold-slot saving (~2,100 gas) applies once-loan-per-block for
the first admin call.

No finding here changes observable contract behavior; all are mechanical refactors.
